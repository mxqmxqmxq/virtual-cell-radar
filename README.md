# Virtual Cell Radar

English | [简体中文](README.zh-CN.md)

Virtual Cell Radar is a live radar of papers and industry news on **AIVC (AI virtual cell)** research. It fetches new papers from arXiv and bioRxiv, pre-filters them by keywords, scores and classifies them with an LLM, writes daily and weekly Markdown reports, and publishes everything as a static website. A second, parallel line collects business news (funding, partnerships, M&A, model or data releases, clinical progress, key hires) from public RSS feeds and a few HTML news list pages and turns it into structured, linked-back entries (see [Business news](#business-news)). A third, semi-static line is a curated directory of repositories, data portals, benchmarks and learning material (see [Knowledge resources](#knowledge-resources)).

```
papers:  fetch  ->  keyword pre-filter  ->  LLM scoring and classification  ->  daily / weekly reports  ->  static site
news:    RSS + HTML list pages  ->  keyword / company pre-filter  ->  de-dup and merge  ->  LLM extraction and relevance  ->  event merge  ->  "Industry news" in reports  ->  static site
resources: curated YAML  ->  GitHub metrics refresh  ->  candidates from papers and news  ->  static site (#/resources)
```

The website is a plain static page (no npm build step). Every visitor can define **their own topics** ("My topics") in the browser and see which papers match them; nothing about those topics is sent to a server.

- Repository: https://github.com/mxqmxqmxq/virtual-cell-radar
- Website: https://mxqmxqmxq.github.io/virtual-cell-radar/
- Licenses: code MIT, project-owned annotations CC BY 4.0, third-party metadata under the terms of each source. See [Data and licenses](#data-and-licenses).
- Roadmap: [docs/ROADMAP.md](docs/ROADMAP.md)

> **Scores are not quality ratings.** `relevance`, `final_score` and `must_read` are automatic labels of how relevant a paper is to the AIVC research scope defined in `config/`. They say nothing about the quality, correctness or merit of a paper. The Chinese summaries (`summary_zh`, `novelty_zh`) are generated by an LLM and may contain errors; always check the original paper.

## Requirements

- [uv](https://docs.astral.sh/uv/) (Python package and environment manager)
- Python 3.11, installed and managed by uv
- Node.js (optional, only for the JavaScript tests)

## Install

```bash
git clone https://github.com/mxqmxqmxq/virtual-cell-radar.git
cd virtual-cell-radar
uv sync
```

Optional: configure an API key for LLM scoring.

```bash
cp .env.example .env
# edit .env and set ANTHROPIC_API_KEY=...
```

`.env` is git-ignored. Without a key the pipeline still runs, see [Behaviour without a scoring backend](#behaviour-without-a-scoring-backend).

## Quick start

```bash
# fetch the last 3 days (default from config/pipeline.yaml), score, write the daily report
uv run python -m aivc update

# last 7 days
uv run python -m aivc update --days 7

# fetch and store only, skip LLM scoring (no key needed)
uv run python -m aivc update --no-llm

# build the site and preview it at http://localhost:8000
uv run python -m aivc build-site
uv run python -m aivc serve
```

## Scoring backends

LLM scoring is selected by `backend` in `config/llm.yaml` (default `auto`):

| backend | Uses | Needs | Good for |
|---|---|---|---|
| `auto` (default) | Anthropic API if `ANTHROPIC_API_KEY` is set, otherwise the local Claude Code | one of the two | everyday local use |
| `api` | Anthropic API, billed per call | `ANTHROPIC_API_KEY` in `.env` or the environment | GitHub Actions and other servers |
| `claude_cli` | local `claude -p`, using your Claude Code subscription | Claude Code installed and logged in | your own machine, no separate key |

With the local Claude Code backend nothing needs to be configured: if `claude` runs in your terminal and is logged in, `update` and `score` use it. It takes roughly 10 seconds per paper (4 in parallel by default), runs without tools, hooks, plugins or MCP, and does not save sessions. It only works on your own machine. Both backends use the same model id and share the scoring cache, so switching backend does not re-score anything.

Scoring settings (`config/llm.yaml`): prompt version `v3`, model `claude-haiku-5-5` (verify that the id is available to your account), `must_read_threshold: 9`. The final score is `relevance x circle weight` (core 1.0, peripheral 0.6); a paper is marked `must_read` when `final_score` reaches `must_read_threshold`. Always read the current value from `config/llm.yaml`.

## Behaviour without a scoring backend

If there is no `ANTHROPIC_API_KEY`, no `claude` command, authentication fails, or the model id does not exist, the pipeline still completes:

- papers are fetched, pre-filtered, de-duplicated and stored, with `llm_status` set to `unscored`;
- reports sort by keyword score and say that the run is unscored;
- the exit code is 0.

Once a key or a Claude Code login is available, score the backlog:

```bash
uv run python -m aivc score
```

A paper is never scored twice: scored records carry `llm_status=scored`, and results are appended to `data/cache/llm.jsonl`.

## My topics

The website has a **My topics** entry in the navigation bar. Each visitor can add topics of their own, for example "spatial omics" with a few keywords, and the site marks every paper whose title, abstract or keywords match.

- **Matching rules (v1).** The text matched is title + abstract + keywords; a topic matches if any of its terms matches. Terms are case-insensitive; spaces and hyphens are equivalent (`single-cell` matches `single cell`); plain English terms also match simple plurals, all-caps acronyms do not (`UCE`); the match must not be glued to a preceding letter or hyphen. A trailing `*` is a prefix match (`transcriptom*`), a leading `*` allows letters before it. Terms containing CJK characters are matched literally as substrings. User input is always escaped, never interpreted as a regular expression. The same rules are implemented in Python (`src/aivc/termmatch.py`) and JavaScript (`src/aivc/web/assets/topics.js`) and checked against shared test cases.
- **Where it is used.** Matching runs in the browser on the already loaded papers: topic tags on paper cards and in the detail drawer, a topic filter in the paper list, and a "this week, related to my topics" block on weekly report pages.
- **Where data is stored.** Topics live only in the browser's `localStorage` of the visitor (key `aivc.topics.v1`). Clearing site data removes them.
- **Sharing.** A topic set can be exported as a link (the payload sits in the URL fragment after `#`, so it is never sent to a server) or as a JSON file. Opening a link or importing a file only shows a confirmation dialog; nothing is merged until the visitor confirms.
- **Presets by the deployer.** `config/topics.yaml` can list public preset topics (`id`, `name`, `terms`, `default_enabled`). Presets appear on the site as selectable topics. `default_enabled: true` means the preset is switched on by default for visitors (they can still turn it off) and is also used for the "Topic tracking" section of the Markdown daily and weekly reports. With `false` it is only an optional preset and does not appear in those reports. The shipped examples are all `false`.
- Limits: up to 20 topics, up to 40 terms per topic.

## Private local profile (`--local`)

For a maintainer who wants private topics or private papers on their own machine, `--local` (or `AIVC_LOCAL=1`) adds a private layer on top of the public data:

- `local/topics.yaml` adds private topics (same format as `config/topics.yaml`);
- `local/data/` holds private papers, for example the output of `seed`; for a paper that is also in the public data only `local_file` and `tags` are taken from `local/`, and papers only present in `local/` are added;
- reports and the site are written to `local/reports` and `local/site`, not to `reports/` and `site/`.

```bash
uv run python -m aivc --local build-site
uv run python -m aivc --local serve --port 8001
```

Isolation guarantees: `local/` is listed in `.gitignore` and never enters the repository; `seed` writes only into `local/data`, so seed material cannot leak into the public data; without `--local` nothing in `local/` is read; `check-public` verifies that private topic names, absolute paths and non-allowed tags do not appear in the public data, reports, site or repository.

## Pipeline description

```
fetch (arXiv, bioRxiv)
  -> keyword pre-filter (core / peripheral circle)
  -> de-duplication (DOI / arXiv id / fuzzy title match)
  -> LLM scoring and field extraction (model in config/llm.yaml)
  -> monthly JSONL storage (data/papers/YYYY-MM.jsonl)
  -> daily Markdown report (reports/daily/YYYY-MM-DD.md)
```

The business-news line has its own pipeline, described in [Business news](#business-news).

- Only papers that pass the keyword pre-filter (core or peripheral circle) are stored, so bioRxiv's many categories do not flood the library.
- De-duplication keys are, in order, `arxiv:<id without version>`, `biorxiv:<id>`, `doi:`, `openreview:`, then exact normalised title and fuzzy title match (threshold `dedup.title_threshold` in `config/pipeline.yaml`).
- `final_score = relevance x circle weight`; `must_read` is true when `final_score` is at least `must_read_threshold` from `config/llm.yaml` (currently 9).

## Weekly reports and the website

```bash
uv run python -m aivc weekly       # latest complete week
uv run python -m aivc build-site   # export to site/
uv run python -m aivc serve        # http://localhost:8000
```

- **Weeks.** Calendar weeks, Monday to Sunday, ids like `2026-W45` (ISO numbering). A paper belongs to the week of its `first_seen` date, not its publication date.
- **Weekly report** (`reports/weekly/YYYY-Www.md`): overview (new papers, circle split, scored vs. unscored), top papers by `final_score` with `novelty_zh`, unscored papers listed separately by keyword score, newly released datasets or benchmarks, paradigm and task distribution compared with the previous week, and, only for topics with `default_enabled: true`, a "Topic tracking" section. When news data exists for the week there is also an "Industry news" section (scored core items, i.e. relevance at least `news.site_min_relevance`, i.e. core items only): major events marked "[major]", the week's top `news.weekly_top_n` events with summary and source links, and a funding table with totals. A week without papers still gets a report if it has news.
- **Optional LLM overview.** Off by default; set `weekly.llm_overview: true` in `config/pipeline.yaml` for a 3 to 5 sentence summary. It uses the same backend as scoring and is skipped silently if none is available.
- **Auto build.** `update` and `weekly` rebuild the site when `site.auto_build` is true (use `--no-site` to skip). A failed build only prints a warning. `score`, `backfill`, `seed` and `reindex` do not rebuild; run `build-site` yourself.
- **Site pages.** Home (`#/`); Paper stream (search, filters by circle, source, scored, must-read, new dataset, task, paradigm, topic, time range; sort by final score, keyword score or date; detail drawer; a paper that mentions a tracked company or one of its models links to that company's profile); Paradigm map (paradigm x task heat map); Datasets / benchmarks; Weekly reports; My topics; **Business news** (`#/news`, three views, see [Business news](#business-news)); **About** (`#/about`: the step-by-step journey of a paper, the four-command terminal walk-through and the FAQ, linked from the home page and the footer); **Knowledge resources** (`#/resources`, see [Knowledge resources](#knowledge-resources)).
- **Access.** Use `serve`; opening `site/index.html` through `file://` cannot load the JSON data. `serve` listens on `127.0.0.1` only. `site/` is generated and git-ignored.

### Home page structure

The home page has five blocks, each answering a different question in a different form (no run of identical card grids):

1. **Hero** - "What is this and how big is it?" Title with a rotating keyword (including "industry news"), entry buttons, key numbers (papers, scored papers, must-reads, industry events in the last 7 days) and the scoring progress bar; WebGL tunnel background with a CSS fallback.
2. **This week at a glance** - "What happened lately?" The main body, laid out as a briefing rather than cards. Left, a numbered ranking of papers (score, title, one-line novelty, topic tags), switchable between "All" and "My topics" (with enabled topics, matching papers are moved up and tagged). Right, three stacked lists: industry news (major events first, linking to `#/news`), new datasets, and paradigm trend changes (this period vs. the previous one). The window is a rolling last 7 days, so it is never empty on Mondays; the head links to the full weekly report.
3. **Field pulse** - "Where is the field heading?" Two charts: the paradigm x task heat map and the quarterly funding bar chart (from news data, links to `#/news?view=funding`).
4. **How it works** - "Where does the data come from and can I trust it?" Data-source chips plus the tabbed pipeline demo, and a link to `#/about`.
5. **Closing** - "How do I make it mine?" A button that opens the My topics panel, links to the paper stream, industry news and weekly reports, and the data generation time.

The step-by-step journey of a paper, the four-command terminal and the FAQ moved from the home page to `#/about`. See [How it works in four commands](#how-it-works-in-four-commands-and-faq) below for the same content in text form.

All content comes from `site/data/*.json` (including `home.json`, `news.json` and `companies.json` written by `build-site`). With `prefers-reduced-motion` no looping or moving animation plays; looping animations pause when off-screen or when the page is hidden. If `home.json` is missing or the home script fails, the site falls back to a simple home page; missing news data shows empty states with the command to run. The front end uses no third-party library.

### How it works in four commands, and FAQ

The same flow the home page used to show as a terminal, and what the `#/about` page covers:

```bash
uv run python -m aivc update       # 1. fetch papers (and news), pre-filter, de-duplicate, store, score, daily report
uv run python -m aivc score        # 2. score papers that are still unscored (after --no-llm or a missing backend)
uv run python -m aivc weekly       # 3. weekly report for the latest complete week
uv run python -m aivc build-site   # 4. export site/ ; then `serve` to preview at http://localhost:8000
```

- *Where does the data come from?* arXiv and bioRxiv are fetched daily and pre-filtered by keywords; OpenReview (ICLR) entries are included as submissions; business news comes from the RSS feeds and HTML list pages listed under [Business news](#business-news). medRxiv and journal RSS are disabled.
- *Where do the scores and "must read" come from?* An LLM rates each paper's relevance; `final_score = relevance x circle weight`; must-read means `final_score >= must_read_threshold`. These are relevance labels, not quality ratings.
- *What do unscored papers look like?* They are stored as unscored, sorted by keyword score in reports and clearly marked on the site; `score` fills them in later.
- *How are weekly reports made?* Calendar weeks (Monday to Sunday, ISO ids), by `first_seen` date.
- *How do I preview locally?* `build-site`, then `serve` (`--port` to change the port).
- *What does the home page do with reduced motion?* No looping or moving animation; final states are shown directly.
- *How do I see only papers for my topic?* Use "My topics" in the navigation bar; topics stay in your browser.

**HTML list-page fetcher** (`src/aivc/fetchers/news_html.py`, standard library `html.parser`, no new dependency). For sites that publish no RSS but whose `robots.txt` and terms do not forbid automated reading of the list page. Each page is configured in the `html_sources` list: `name`, `list_url`, `kind`, `company`, `link_pattern` (regular expression an entry link must match), optional `exclude_pattern`, `same_host_only` (default true), `min_title_chars` (default 15), `max_items` (default 30), `require_date` (default true), `date_scope` (where to look for the date relative to the link: `inside`, `after`, `before`, `before_nearest` or `auto`, default `auto`; `before_nearest` takes the nearest date before the anchor, for pages where the date opens the card and the link closes it), `date_lookback_chars` (only for `before_nearest`: how far back to look, default 1500), `prefilter` and `strict_terms` (as for RSS, below) and `title_strip_patterns` (a list of regular expressions; each match is removed from the title candidate before the length check, for example to drop a category prefix or a trailing byline; default empty, i.e. no cleaning). Constraints: it reads only the **list page** (never an article page); extracts only **title, link and date**; the snippet is always empty and no body text is stored; entries without a parsable date are dropped; `robots.txt` is respected; at least 1 second between requests; a source that fails never stops the others. Every new HTML source has an offline fixture test in `tests/test_news_html.py`.

Not enabled, with reasons recorded in comments in `config/sources.yaml` and in [DATA_LICENSE.md](DATA_LICENSE.md): FierceBiotech, Endpoints News and Recursion investor news (HTTP 403); BioPharma Dive, NVIDIA blog, PR Newswire and Substack newsletters (terms bar automated access); Nature journals (robots.txt blocks AI crawlers and the terms bar building a database from feeds); Science news (robots.txt blocks AI crawlers, terms page unreadable); MIT Technology Review, Pharmaceutical Technology and Insilico Medicine (robots.txt restrictions); GlobeNewswire (no official feed URL could be confirmed). Most other company sites publish no RSS feed. BiopharmaTrend's feed has no dates, so its dates are read from the article page (`date_from_article`). To add or remove a source, edit `feeds` or `html_sources` (RSS: `name`, `url`, `kind` = `media` or `company`, `company`, `enabled`, `prefilter` = `default`, `strict` or `none` (`none`: no pre-filter, items go straight to the LLM for scoring; only for low-volume, fully on-topic official press-release sources, currently Biohub News), `strict_terms`: the source's own word list for strict pre-filtering, which replaces the global `news.strict_keywords` when non-empty); verify `robots.txt`, the terms and the HTTP status first. Source terms are summarised in [DATA_LICENSE.md](DATA_LICENSE.md); entries marked "待核实" there are not yet confirmed.

**Pipeline.**

```
RSS and HTML list-page fetch (robots.txt respected, >= 1 s between requests)
  -> article-date lookup (only for feeds marked `date_from_article`, for entries without a pubDate; see below)
  -> pre-filter (keywords in pipeline.yaml news.keywords, or a tracked company name, plus combination rules: AI + biology, funding + AI, round-ups; company sources must match too; sources with `prefilter: strict` must also match the strict word list)
  -> de-duplication (normalised URL, fuzzy title match; same story from several outlets keeps all source links)
  -> LLM extraction and relevance 0-10 (prompt news-v6.1, own cache data/cache/news_llm.jsonl)
  -> event merge (same event type + company + date window + amount across outlets)
  -> major-event rules
  -> data/news/YYYY-MM.jsonl
  -> daily report (pinned major events), weekly report ("Industry news"), site/data/news.json and companies.json
```

**Strict pre-filter and Chinese matching.** General tech media and general AI podcasts (Qbitai, ITHome, Leiphone, 36Kr, Latent Space) are high-volume and noisy, so they carry `prefilter: strict`: an item's title and snippet must match `news.strict_keywords` in `pipeline.yaml` (bilingual) or the source's own `strict_terms`; matching only a company name or a combination rule is not enough. The news pre-filter treats terms containing Chinese characters specially: spaces at the boundary between Chinese characters and Latin letters or digits do not affect matching, and matching is case-insensitive, so "AI制药" and "AI 制药" are equivalent and the AI in "用AI设计蛋白" can satisfy a combination rule; fuzzy title de-duplication lowers the minimum length for titles containing Chinese characters from 20 to 10 normalised characters. The prompt is still `news-v6.1` and summaries are still written in Chinese. The LLM backend is chosen exactly as for papers (see [Scoring backends](#scoring-backends)). Without a backend, or with `--no-llm`, items are stored unscored and a later `news` run scores them when the feed still lists them (otherwise from the title alone). `news.max_llm_calls_per_run` caps LLM calls per run. **Article-date lookup.** Some feeds carry no publication date per entry (BiopharmaTrend). For a feed marked `date_from_article: true`, entries without a pubDate trigger a request to the article page, and only the publication date is read (`article:published_time`, JSON-LD `datePublished`, `<time datetime>`; modified dates are ignored). `robots.txt` is respected (a disallowed page is skipped), at least 1 second passes between requests, `news.max_date_lookups_per_run` (default 20) caps lookups per run, and results are cached in `data/cache/news_dates.json` (URL and date only; a miss is retried after 7 days). No article body is stored. Entries that still have no date are dropped when `require_date` is true.

Prompt `news-v6.1` scores relevance to the virtual-cell direction (cell-level AI modelling) rather than to AI drug discovery in general, on four tiers: 9-10 for major events in virtual cells, cell foundation models, and perturbation maps or large perturbation datasets; 7-8 for financings, collaborations and releases from companies whose core business is cell modelling, perturbation screening, or single-cell, multi-omics or phenotypic AI platforms, and for large-pharma collaborations that target cell-level modelling or perturbation data; 6 for AI drug-discovery or AI-biology news in which the cell, omics or phenotypic-screening component is an important part of the event (the snippet must name a concrete cell-level model, dataset or screening platform; pure biology findings or atlases without an AI or modelling component get at most 5), and 5 where that component is only a side note (v6 describes 5 and 6 separately, v5 had them as one "5-6" tier; v6.1 adds the two restrictions above), plus an exception: analysis, tracker or interview pieces whose subject is itself virtual cells, cell foundation models or large perturbation or single-cell data get 5 and never more; 4 or below for general AI drug discovery (molecule generation and design, clinical progress and approvals of AI-derived drugs), general AI products, and laboratory automation unless it directly produces perturbation data. Deal size, company fame and clinical stage alone do not lift an item above 5 without a cell-level component, and cell therapy is not cell modelling. The v4 rules carry over: general-audience explainers, interviews and opinion pieces, round-ups, brand events, non-biomedical business, framework agreements outside biomedicine, and generic posts from research institutions or technology-company blogs are scored low; other opinion, interview, round-up and analysis pieces are capped at 4 even when they mention a deal; and rumoured or in-negotiation financings, philanthropic or institutional grants, or a VC firm's own fundraising do not count as `funding` amounts. With `--rescore-stale`, stored items that still carry an older prompt version are re-scored with the current prompt when they appear in a new fetch (stored items keep no snippet, so items that no longer appear in any feed keep their old score). `aivc news-rescore` is a separate command that re-scores only items already in the library: it re-fetches the enabled sources only to recover each item's snippet (it never stores new items), falls back to the stored summary when a snippet cannot be recovered, and enforces a hard cap on real LLM requests including retries (`--max-requests`). `--ids` selects items, `--include-unscored` adds unscored items, `--dry-run` only lists the plan, `--no-fetch` skips the re-fetch, `--days` sets the look-back window, and `--no-site` skips the site rebuild.

**Display limits.** Two tiers share one filter (`news.publishable`) and both require a publication date. **Core items** have `relevance >= news.site_min_relevance` (default 6; 6 and above is reserved for items with an explicit cell, omics or phenotypic component). **Related items** have `relevance` from `news.site_related_min_relevance` (default 5) up to the core threshold; they appear only in a collapsible "Related" section on the site's news page (open by default when there are fewer than 8 core items). The home-page briefing, the statistics, company profiles, funding totals and the weekly report use the core threshold only. Items without a date are never shown, never enter the weekly report and never count towards funding totals (a feed entry may set `require_date: true` to drop undated entries at fetch time; BiopharmaTrend does and also sets `date_from_article`, so its dates now come from the article page; the 7 undated items it left in the library were marked `llm_status: unscored`, `llm_skip_reason: undated_excluded` with their old v3 scores cleared, and can be dated and scored when the feed lists them again). On top of that, one company is capped at `news.max_per_company_per_week` (default 3) items per week and at `news.max_per_company_per_30d` (default 4) items in any 30 consecutive days (`<= 0` disables a cap), so a single source company cannot dominate. The weekly groups on the news page and the home-page briefing sort by relevance; within equal scores, companies alternate (round-robin) before date is used.

**What is stored, and what is not.** Only the title, link, source name(s), publication time, and a Chinese summary and key point that the LLM writes in its own words are stored and shown. **Major events.** The `major` list in the `news` section of `config/pipeline.yaml` holds the rules; an item matching any rule is marked major, pinned at the top of the daily report that day and listed first in the weekly "Industry news" section. Each rule has an `id`, a `label`, `event_types`, and optionally `min_amount_usd` and `company_tier` (`top` is set per company in `companies.yaml`). Shipped rules: funding of at least 100 million USD, and a model or data release by a top-tier company. Push notifications are **not implemented**: only the interface (the `major` flag and the list of major items of a run) exists, nothing is sent to any external service.

**On the site** (`#/news`): a **timeline** grouped by week, filterable by event type, company and amount, with search and a "major only" switch (filters are kept in the URL); a **funding summary** (`#/news?view=funding`, quarterly bar chart and the list of funding events); a **company list** (`#/news?view=companies`) and **company profiles** (`#/news/company/<id>`) with the company's news, its models, and the papers in the library that mention the company or its models (matched with whole-word matching on `paper_terms` in `companies.yaml`; a paper's detail drawer links back to the profile).

**Caveats.**
- "Cumulative funding" on company pages and the funding summary is only the sum of funding events **already in this library whose amount was disclosed**. It is not the company's total funding and not a complete funding database.
- Summaries and key points are produced by an LLM and may be wrong or incomplete; check the original article before relying on them. Relevance is a relevance label, not a judgement of the company or the news.
- Politeness: requests carry the User-Agent from `sources.yaml` (`virtual-cell-radar/0.1 (+https://github.com/mxqmxqmxq/virtual-cell-radar)`), `robots.txt` is checked per host, and at least 1 second passes between requests.
- A source (RSS or HTML) that fails does not stop the run; the run fails only when every enabled source fails.

## Knowledge resources

A curated, semi-static directory of the places a newcomer to AIVC should know, shown in five sections: labs and teams, representative repositories (plus a few foundational tools), key datasets and benchmarks, reviews and blogs (including talks), and community-maintained lists (awesome lists, linked only). It is meant to be selective, not exhaustive, and is maintained monthly. It holds public resources only.

```bash
uv run python -m aivc resources list                  # grouped by kind, with stars, last push, maintained or not
uv run python -m aivc resources check                 # offline validation, exit code 1 on problems
uv run python -m aivc resources refresh               # fetch GitHub metrics (needs network)
uv run python -m aivc resources discover              # extract candidates from papers and news (offline)
uv run python -m aivc resources accept ID --url URL   # move a candidate into the curated list
uv run python -m aivc resources archive ID
uv run python -m aivc update --refresh-resources      # papers/news update, then refresh metrics (off by default)
```

**Data layout** (`data/resources/`):

| File | Content | Written by |
|---|---|---|
| `labs.yaml` | labs, research teams and institutes (`lab`), 27 entries (7 based in China) | by hand |
| `repos.yaml` | repositories (`repo`), 22 entries | by hand |
| `tools.yaml` | foundational tools (`tool`), 8 shown, 6 generic ones archived | by hand |
| `data.yaml` | data portals (`data_portal`) and benchmarks (`benchmark`), 13 + 7 entries | by hand |
| `learning.yaml` | reviews, blogs and reports, talks, courses, tutorials, 28 shown | by hand |
| `community.yaml` | community-maintained collections (`awesome_list`), 3 entries | by hand |
| `candidates.yaml` | auto-discovered or pending items (`candidate`, `archived`) | `aivc resources` |
| `github_metrics.json` | GitHub metrics per repository, fetch time, monthly star snapshots | `aivc resources refresh` |

The curated list currently holds **108 accepted resources** (lab 27, repo 22, tool 8, data_portal 13, benchmark 7, review 16, blog 7, podcast 2, tutorial 2, course 1, awesome_list 3). Every URL was requested when the list was compiled and entries that could not be confirmed were left out. Descriptions are written by this project in its own words and only state verifiable facts. Metrics live in their own JSON file so monthly refreshes do not disturb hand edits; the curated files are rewritten only when `accept` moves a candidate into one (hand-written comments in them are not preserved, so put remarks in the `note` field).

**Fields** (`Resource` in `src/aivc/models.py`):

| Field | Meaning |
|---|---|
| `id`, `name`, `url` | slug id (lowercase letters, digits, hyphens; unique), name, link (http or https) |
| `kind` | `repo`, `tool`, `data_portal`, `benchmark`, `course`, `review`, `tutorial`, `blog`, `podcast` or `other` |
| `description_zh` | Chinese description in the project's own words (at most 300 characters; checked by `check-public`) |
| `tags`, `related_tasks`, `related_paradigms` | free tags and ids from the taxonomy in `config/scope.yaml` (`check` rejects unknown ids) |
| `status` | `accepted` (shown), `candidate` (pending review), `archived` |
| `added`, `source` | date added; `manual` or `auto_discovered` |
| `github` | `owner/repo` used for metrics (derived from `url` when it is a repository URL) |
| `paper_ids`, `dataset_names`, `discovered_from`, `note` | links to library papers, dataset names or aliases used for linking with the datasets page, discovery provenance, remarks |

**GitHub metrics.** `resources refresh` calls the GitHub REST API for each curated repository and records stars, last push time, archived flag, license identifier (as returned by GitHub, not interpreted) and main language, together with the fetch time and a monthly star snapshot (so a star change can be shown after the next monthly refresh). An optional `GITHUB_TOKEN` environment variable is sent as a bearer token; without it the anonymous limit of **60 requests per hour** applies, and when the limit is reached the run stops gracefully and reports how many repositories were not processed (nothing is lost; run it again later). Repositories fetched less than `resources.refresh_min_interval_days` (25) days ago are skipped unless `--force` is given. The first real refresh used 42 requests; all 42 repositories were found and no error occurred.

**"Still maintained".** A repository counts as maintained when it is not archived and its last push is at most `resources.maintained_within_days` (default 365) days ago, computed against today's date when the site is built (not stored). Resources without GitHub metrics (data portals, courses and so on) have no maintained flag and are never filtered out by it. This is a simple activity rule, not a quality judgement: a finished, stable repository may be marked inactive.

**Auto-discovery.** `resources discover` is offline. It extracts GitHub repository links from the papers' `code_url` and abstracts, and dataset names from `llm.datasets_used` (mentioned in at least `resources.discover_min_dataset_mentions` papers, default 3) and `llm.new_dataset_names`, plus repository links found in news. Results are written to `candidates.yaml` with `status: candidate`; nothing enters the curated list automatically. The paper library has very few repository links, so repository candidates are rare (1 so far), and most candidates are dataset names, including noisy cell-line names, that need manual screening. `accept` moves a candidate into the right curated file (a dataset candidate has no URL, so `--url` is required); `archive` stops a candidate from being rediscovered and hides a curated entry from the site.

**On the site** (`#/resources`, data from `site/data/resources.json`): resources grouped by kind and filterable by kind, task, paradigm, maintained status and star range, with search; the filter state is kept in the URL (`#/resources?kind=&task=&paradigm=&maintained=&stars=&q=`). Repository cards show stars, last push date, main language, license and an archived or inactive badge. Task and paradigm tags link to the paper stream; dataset names link to the paper search, and datasets in the datasets page link back to their resource (`#/resources?id=`); when `paper_ids` are set, a paper's detail drawer shows related resources (no curated entry has `paper_ids` yet). **Candidates and archived entries are not exported and not shown on the public page.** The home page links to the page from its closing section.

Resource licenses: this project stores only name, link and its own Chinese description; the license of each resource is whatever its website or repository states (the license identifier shown on cards is relayed from the GitHub API). Most data-portal licenses in `data.yaml` are still marked "待核实". See [DATA_LICENSE.md](DATA_LICENSE.md).

## Configuration

All configuration lives in `config/*.yaml` and takes effect on the next run.

- **keywords.yaml**: keyword pre-filter. Each group in `groups` has a `circle` (`core` or `peripheral`) and a `weight`; matched weights add up to `keyword_score`; `circle` is the highest-priority circle among matched groups. `min_keyword_score` is the storage threshold, `exclude_terms` are excluded terms. A group may use `all_of: [[A terms], [B terms]]` (at least one term from every sub-list must match) for combinations like method term + biological context. Matching rules are the ones described under [My topics](#my-topics). Run `reindex` after editing.
- **sources.yaml**: source switches and parameters (`arxiv`, `biorxiv`, `medrxiv`, `journals_rss`, `openreview`, `news`, `http`, `seed`). medRxiv and journal RSS are disabled. The `news` section (it replaces the former `news_rss` section) holds `enabled`, `delay_seconds`, `user_agent`, `respect_robots` and the `max_date_lookups_per_run` (default 20) and the `feeds` list (26 enabled; each feed accepts `require_date`, `date_from_article`, `prefilter` and `strict_terms`) described in [Business news](#business-news). The `news` section also holds the `html_sources` list (HTML list pages, which also accept `date_scope: before_nearest` and `date_lookback_chars`; see [Business news](#business-news)). `openreview` also holds `api_base_url` and `delay_seconds` used by `refresh-openreview`. `seed.source_dir` is the default seed folder.
- **scope.yaml**: circle weights (core 1.0, peripheral 0.6) and the `taxonomy` of `tasks` and `paradigms` used by the LLM.
- **llm.yaml**: `model`, `max_tokens`, `prompt_version` (`v3`), `max_calls_per_run`, `concurrency`, `must_read_threshold` (9), `abstract_max_chars`, `cache_file`, `backend`, `cli_command`, `cli_timeout`.
- **pipeline.yaml**: `update.default_days`, `backfill_chunk_days`, `dedup.title_threshold`, `report.max_items`, `weekly.*` (`top_n`, `max_unscored`, `max_per_topic`, `llm_overview`, `overview_model`, `overview_max_tokens`), `site.*` (`auto_build`, `port`, `top_datasets_used`), `public.allowed_tags` (tags allowed in public records; everything else counts as private), and the `news` section: `run_with_update`, `default_days`, `keywords` (pre-filter), `strict_keywords` (bilingual word list for strict pre-filtering), `title_threshold` (fuzzy de-dup), `merge_window_days` (event merge window), `max_llm_calls_per_run`, `company_feed_requires_match`, `max_per_company_per_week`, `max_per_company_per_30d`, `rescore_stale_max_calls`, `prompt_version` (`news-v6.1`), `model`, `cache_file`, `site_min_relevance` (6), `site_related_min_relevance` (5), `weekly_top_n` and the `major` rules; and the `resources` section: `maintained_within_days`, `refresh_min_interval_days`, `max_requests_per_run`, `request_delay_seconds`, `run_with_update`, `github_api_base`, `discover_min_dataset_mentions`.
- **topics.yaml**: public preset topics for visitors, see [My topics](#my-topics).
- **companies.yaml**: the tracked companies, used by the news pipeline for matching and for company profiles. Fields: `id` (used in profile URLs), `name`, `aliases` (alternative names for matching), `url`, `category` (`research_institute`, `biotech`, `pharma`, `big_tech`, `philanthropy`, `other`), `tier` (`top` marks a leading institution, used by the major-event rules), `models` (public models or datasets, shown on the profile) and `paper_terms` (distinctive names matched with whole-word matching against paper titles and abstracts to link papers and companies; never short or common words such as "Arc" or "State"). Only public information.

Environment variables: `ANTHROPIC_API_KEY`, `GITHUB_TOKEN` (optional, only for `resources refresh`), `AIVC_CONFIG_DIR`, `AIVC_DATA_DIR`, `AIVC_SITE_DIR`, `AIVC_LOCAL`, `AIVC_LOCAL_DIR`, `AIVC_SEED_DIR` (see `.env.example`).

| `first_seen` | date | Date the paper first entered the library |
| `local_file` | str or null | Used only by the private local profile (path relative to a seed folder, never absolute). Always empty in public data. |
| `schema_version` | int | Currently 1 |

News items and resources have their own formats (see the field tables under [Business news](#business-news) and [Knowledge resources](#knowledge-resources)).

The `Paper` model has a few more optional fields (`venue`, `updated`, `version`, `keywords`, `affiliations`, `code_url`, `alt_ids`, ...). The LLM cache is `data/cache/llm.jsonl` (append-only).

## Deploy to GitHub Pages

The site is published at https://mxqmxqmxq.github.io/virtual-cell-radar/ (it returns 404 until the first successful `Pages` run). The repository ships three GitHub Actions workflows in `.github/workflows/`:

- `ci.yml`: on every push and pull request, installs with `uv sync --locked` (so `uv.lock` must be committed and in sync with `pyproject.toml`), then runs `uv run pytest -q`, `node --test "tests/js/*.test.mjs"` (Node 22) and `uv run python -m aivc check-public`. It uses no secret.
- `pages.yml`: on push to `main`, manually (**Actions -> Pages -> Run workflow**), or after a successful `Daily update` run, runs `uv run python -m aivc build-site` and deploys `site/` to GitHub Pages. The build uses only the committed `data/`, `reports/`, `config/` and resources data (`site/` and `local/` are git-ignored). All site paths are relative, so it also works under a sub-path such as `https://<user>.github.io/<repo>/`.
- `daily.yml`: manual only (`workflow_dispatch`); the `schedule` block is commented out because enabling it incurs LLM API cost. It runs `uv run python -m aivc update` (which also fetches news unless disabled), `check-public`, and commits changes under `data/` (including `data/news/`) and `reports/`. It needs the secret below for scoring and a default branch that lets the bot push. `pages.yml` redeploys after it succeeds, because a push made with the default `GITHUB_TOKEN` does not trigger a `push` event.

Steps:

1. Push the code to https://github.com/mxqmxqmxq/virtual-cell-radar on the `main` branch (for a fork or copy, push to your own repository; the Pages address then changes accordingly).
2. Open the **Actions** tab and enable workflows if GitHub asks.
3. In **Settings -> Pages**, set **Source** to **GitHub Actions**.
4. Trigger the first deployment by pushing to `main` or by running the `Pages` workflow manually; the `github-pages` environment then shows the address.
5. Optional: for scoring in `daily.yml`, add the secret `ANTHROPIC_API_KEY` under Settings -> Secrets and variables -> Actions. API usage is billed to you. Without the secret, the pipeline skips scoring and still finishes. To run it on a schedule, uncomment the `schedule` lines in `daily.yml`.

The workflows pin `actions/checkout@v7`, `astral-sh/setup-uv@v10.3.3`, `actions/setup-node@v7`, `actions/configure-pages@v6`, `actions/upload-pages-artifact@v5` and `actions/deploy-pages@v5`, checked against the actions' releases in 2026-11; re-check them from time to time.

## Pre-release check

```bash
uv run python -m aivc check-public
```

It is read-only and returns 0 when nothing is found. It checks that public data records have no `seed_pdf` source, no `local_file` and no tags outside `public.allowed_tags`; that reports, site data and repository text files contain no absolute local paths (URLs such as `.../news/home/...` are not mistaken for paths); that every `data/resources/*.yaml` entry and `github_metrics.json` and the `items` of `site/data/resources.json` have http(s) links and a `description_zh` of at most 300 characters; that every `data/news` record and the `items` of `site/data/news.json` use only the allowed keys, have http(s) links, a title of at most 300 characters, `summary_zh` of at most 400 and `significance_zh` of at most 200 characters, and contain no run of 25 or more consecutive English words (a sign of a long quotation); and, when `local/topics.yaml` exists on your machine, that none of your private topic names appear in public places (this step is skipped, with a note, where `local/` does not exist, such as in CI). Fix every reported item before publishing.

## Privacy

- Topics are stored only in the visitor's browser (`localStorage`); the site has no account system and no server-side storage.
- A share link carries the topics inside the URL fragment (after `#`). Browsers do not send fragments to servers, so the content is not transmitted when the link is opened or when the page loads.
- The page makes one third-party request: it loads fonts from Google Fonts (`fonts.googleapis.com`, `fonts.gstatic.com`), which reveals the visitor's IP address to Google. Offline or when blocked, the page falls back to system fonts and keeps working.
- The static site does not use cookies or analytics scripts. Your hosting provider (for example GitHub Pages) has its own access logs.

## Known limitations

- Scores measure relevance to the AIVC scope, not paper quality; the LLM output (scores, classifications, Chinese summaries) can be wrong.
- Model id `claude-haiku-5-5` must be available to your account; otherwise papers stay unscored.
- bioRxiv `published` is the version date, so older papers can land in earlier monthly files.
- Seed material has no abstract and is not scored; it exists only in the private local profile.
- medRxiv, journal RSS and further conferences are not implemented yet. See [docs/ROADMAP.md](docs/ROADMAP.md).
- News coverage depends on the 31 enabled sources and the keyword pre-filter; it is not a complete record of the industry. With the virtual-cell scoring, the site shows 4 core items (threshold 6) and 12 related items (relevance 5) from a 60-day window, so virtual-cell news coverage is still thin; the sources that focus on the direction publish little, the pre-filter sees only titles for HTML sources. Chinese-language media are connected only through four RSS feeds (Qbitai, ITHome, Leiphone, 36Kr); they keep only a few hours to a day or two of items, so they cannot be backfilled and one run per day misses part of each day's stories (ITHome covers only about 5.75 hours); sources without a usable RSS or whose terms bar republication, such as Cailianshe, are not connected, and WeChat official accounts are not connected; Latent Space is enabled on the author's confirmation (only its main feed; the podcast feed stays disabled), interviews score at most 5, and they are scored from the title and one line of summary only. Several terms pages are still marked "待核实" in [DATA_LICENSE.md](DATA_LICENSE.md). Funding totals only count events in the library, see [Business news](#business-news).
- Whether the license of a preprint allows redistributing its abstract is still being verified; see the open items in [DATA_LICENSE.md](DATA_LICENSE.md).
- Resources: most data licenses in `data/resources/data.yaml` are still "待核实"; the maintained flag is a push-date rule; star growth is only available after a second monthly refresh; auto-discovery yields few repositories and many noisy dataset names; no curated entry has linked `paper_ids` yet.
