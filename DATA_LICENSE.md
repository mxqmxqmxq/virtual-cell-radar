### Important caveats / 重要说明

1. **Machine-generated.** `summary_zh`, `novelty_zh` and the classifications are produced by a large language model. They can be wrong or incomplete and **do not represent the views of the original authors**. Check the original paper.
   中文：中文总结与创新点由机器生成，可能有误，不代表原作者观点。
2. **Scores are not quality ratings.** `relevance`, `final_score` and `must_read` only measure automatic relevance to the AIVC (AI virtual cell) research scope defined in `config/`. They are **not an evaluation of a paper's quality, correctness or merit**.
   中文：分数仅是与 AIVC 研究范围的相关度自动标注，不是对论文质量的评价。
3. **ICLR submissions under review.** Entries with source `openreview` are submissions to a conference, collected from OpenReview. They may be under review, rejected or withdrawn, are not peer-reviewed publications, and their content can change or be removed by the authors. Inclusion implies no endorsement, acceptance or ranking by this project.

## 6. News sources / 新闻来源

The business-news board (Phase 3) reads public RSS feeds and, for a few sites without a feed, the public HTML news **list page** (the HTML list pages, including Biohub News added on 2026-11-15, are read only for title, link and date). Article pages are requested only for sources marked `date_from_article` in `config/sources.yaml` (currently BiopharmaTrend, whose feed items carry no publication date): for an item without a date the fetcher reads that one article page, honours `robots.txt`, waits at least 1 second between requests, caps the lookups per run, keeps only the publication date (cached with the URL in `data/cache/news_dates.json`) and never stores the article body. Feeds, list pages, `robots.txt` and the terms pages below were read on **2026-11-15**. For each news item this project stores only the **title, link, source name, publication time and a Chinese summary / key points written by an LLM in its own words** (the latter are project-owned annotations under section 2). It does **not** store or display article full text or long quotations; feed snippets are passed to the LLM in memory and are never written to disk (HTML list pages provide no snippet at all). Every item on the site links back to the original article and names its source. Rights holders may ask for removal under section 5, which also covers news items. The project sends the User-Agent `virtual-cell-radar/0.1 (+https://github.com/mxqmxqmxq/virtual-cell-radar)`, respects `robots.txt`, and waits at least 1 second between requests.
中文：新闻只保存标题、链接、来源名、发布时间，以及 LLM 用自己的话写的中文摘要/要点；不保存、不展示原文全文或长段引用；站点上每条都链接回原文并标明来源。

## 7. Knowledge resources / 知识资源

The knowledge-resources board (Phase 4) is a curated directory in `data/resources/`. Each entry stores only a **name, a link and a Chinese description written by this project in its own words**, plus tags and classification ids. These are project-owned annotations under section 2 (CC BY 4.0). The project does **not** copy third-party content (README text, documentation, dataset files, review text or course material) into the repository.
中文：资源条目只存名称、链接和本项目自写的中文描述（自有标注，沿用第 2 节许可）；不复制第三方内容。

- **The resources themselves keep their own licenses.** Code, data and text behind each link are governed by the terms of the repository, data portal, publisher or course that provides them. Most data-portal licenses in `data/resources/data.yaml` are marked **待核实**; only a small number were checked (for example, a Hugging Face dataset page showing CC0 and a figshare record showing CC BY 4.0). A link here is not a statement that the resource may be reused for any purpose. A first batch was re-checked on 2026-11-15 (for example the scPerturb Zenodo record is CC BY 4.0, the JUMP Cell Painting Gallery data are CC0 1.0, and the code licenses of PerturBench, PertEval and scPerturBench are BSD-3-Clause, MIT and GPL-3.0); the per-resource results are in section D of [docs/AUTHOR_REVIEW.md](docs/AUTHOR_REVIEW.md), and the notes in `data.yaml` are not all updated yet.
- **License identifiers on cards.** For repositories the site shows the license identifier returned by the GitHub REST API (SPDX id, for example `MIT`), relayed as is and not interpreted.
- **GitHub metrics.** Stars, last-push time, archived flag, license identifier and main language are fetched with `aivc resources refresh` from the GitHub REST API (https://api.github.com), anonymously (60 requests per hour) or with the user's optional `GITHUB_TOKEN`, with at least 1 second between requests. Only these few numeric or identifier fields are stored, in `data/resources/github_metrics.json` with the fetch time. The GitHub Terms of Service (section H) and Acceptable Use Policies, and the REST API rate-limit page (60 unauthenticated requests per hour), were read on 2026-11-15: they allow API access within the rate limits and permit research use of public, non-personal information; collection through the API is not treated as scraping (https://docs.github.com/en/site-policy/github-terms/github-terms-of-service, https://docs.github.com/en/site-policy/acceptable-use-policies/github-acceptable-use-policies, https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api). This project stores only the few non-personal fields listed here. Closed.
- **Auto-discovered candidates** (`candidates.yaml`) come from this project's own paper and news data (links found in `code_url` and abstracts, dataset names extracted by the LLM). They are not shown on the public page until a maintainer accepts them. Dataset names alone are facts, not copyrighted text.
- **Links only.** Some resources are on sites whose terms bar automated access (for example Substack newsletters, which are not enabled as news sources in section 6). They appear in the directory as plain links; this project never fetches those pages.
- Rights holders who want a resource removed or its description corrected: section 5 applies.
